# C4 技能提交自动评审器（skill-evaluator）

## 一句话

给定一个装满 C4 提交的文件夹，自动按作者分组，检查五文件完整性、按四条件打质量分，吐出一份带依据的评审报告 + Excel 可开的详表。

## 输入（Input）

- **文件夹路径**：包含若干作者的 C4 提交，命名遵循 `姓名拼音_C4_内容描述.扩展名`（如 `宋俊毅_C4_skill说明.md`、`李四_C4_demo.png`）。
- 可含按作者分子目录的结构（递归扫描）。

## 输出（Output）

- `评审报告.md`：总览排名表 + 每位作者的完整性逐项 ✅/❌ + 四条件判定（✅/⚠️/❌）+ 命中信号依据 + 综合分/评级。
- `评审详表.csv`：一作者一行，可 Excel 打开，字段含排名/作者/完整数/完整性分/质量分/综合分/评级/四条件判定。

## 使用方法

```bash
python3 skill-evaluator/scripts/evaluator.py <提交文件夹> --out 评审报告.md --csv 评审详表.csv
```

零依赖，仅用 Python 标准库。评审规则固化在脚本顶部 `REQUIRED_FILES` 与 `QUALITY_CRITERIA` 两个字典里，与 `references/c4_rubric.yaml` 同源，改规则改一处即可。

## 评审维度（两层）

### 第一层：C4 五文件完整性（占综合分 40%）

| 必须文件 | 文件名信号 | 内容信号 | 扩展名 |
|---|---|---|---|
| Skill 说明 | skill说明/skill_doc/skill-doc | 使用场景/输入/输出/解决什么问题 | .md/.pdf/.docx |
| 可执行内容 | 技能/skill | ``` 代码块 / def / class / import / frontmatter | .skill/.py/.md/.zip |
| Demo | demo/演示/截图/screen/录屏 | — | .mp4/.mov/.webm/.png/.jpg/.gif |
| 教学说明 | 教学说明/教学/tutorial/how-to | 上手/步骤/常见坑/安装/注意事项 | .md/.pdf/.docx |
| AI日志 | AI日志/AI_log/ai-log | 使用的AI/prompt/迭代/ChatGPT/Claude/DeepSeek | .md/.pdf/.docx |

完整性分 = 命中文件数 / 5。

### 第二层：四条件质量（占综合分 60%，各 0.25）

可复用 / 可执行 / 可验证 / IO明确。每个条件按「正信号命中率 − 负信号惩罚」映射为 ✅(1.0)/⚠️(0.5)/❌(0.0)，并把命中的信号写进报告作为**评审依据**（不是黑箱）。

- **可复用**：有安装/环境说明、无硬编码绝对路径（`/Users/`、`C:\`）、注明平台、依赖可获取。
- **可执行**：含可运行代码/prompt/workflow、.skill 包结构有效、SKILL.md 含 frontmatter。
- **可验证**：有测试用例/示例、定义预期输出、demo 展示真实结果、成败标准清晰。
- **IO明确**：有「输入X→输出Y」一句话、明确输入/输出类型与格式、注明边界输入。

### 综合分与评级

```
完整性分 = 命中文件数 / 5
质量分   = (可复用 + 可执行 + 可验证 + IO明确) / 4
综合分   = 完整性分 × 0.4 + 质量分 × 0.6
评级     = ≥0.8 A / ≥0.6 B / ≥0.4 C / 否则 D
```

> 说明：C4A 挑战正文的四条件各占 0.25，是「质量层」的内部权重；`完整性×0.4 + 质量×0.6` 是把「完整性」和「四条件质量」合成一个可排序总分时的实现口径。对外评审仍按 rubric 维度逐项给出，不丢维度。

## 评审流程（Level 1→4）

1. **采集**：递归扫描，按 `_C4_` 前缀解析作者，无法解析的归入「_未分类」。
2. **完整性**：逐作者判定五文件是否命中。
3. **质量**：逐作者对四条件做信号命中打分，记录正/负信号证据。
4. **报告**：总览 + 逐作者明细，输出 Markdown 与 CSV。

## 边界与人工 Gate

- 本评审器是**规则引擎初筛**：它判断「文件在不在、信号有没有」，不替代人工对内容质量的最终判断。适合初筛、互评一致性校准、助教批量预读。
- **不伪造证据**：信号命中列的是「真的匹配到了哪个关键词/模式」，没命中就是「—」。
- 对复杂/边界提交，建议：先跑本脚本得到初筛分与证据，再人工复核报告中的判定项。
